What it is

Not a model. An autonomous R&D loop that builds and verifies models for you.

Recursive self-improvement

Reads its own diagnostics each round and proposes better candidates; memory carries lessons across datasets.

Parallel GPU fan-out

Dozens of candidate trainings per round across parallel workers, GPU or CPU, never faking hardware.

Frozen certification core

Selection on validation only; the sealed test is peeked exactly once, by code the search can never touch.

Literature-grounded proposals

A live scout feeds arXiv and Hugging Face abstracts into the proposer, so candidates reflect current technique.

Five modalities, one contract

Tabular, vision, text, time-series and ranking, each with its own frozen certifier behind one interface.

Governed autonomy

An LLM reads your free-text goal; a per-day spend cap bounds GPU and LLM cost.

The recursive loop

Propose. Fan out. Measure. Diagnose. Improve. Then prove it, once.

Architecture

Built like real infrastructure, not a notebook.

  • One worker contract, every laneEach round serializes every candidate into the same JobSpec and dispatches it through a worker contract: remote GPU workers with client-side concurrency control, or a local CPU pool. The winner is certified from the worker's returned predictions, never a locally re-fit copy. JobSpec { op: "fit_val", family: "poly2+scale+logreg", params: {…}, seed: 7, metric: "accuracy", Xtr, ytr, Xva } // yva never ships: scored locally
  • A casebase that transfersOn a new dataset the engine looks up the most similar past runs by dataset signature (size, dimensionality, class balance) and seeds round one with the moves that actually paid off there. Realized gains are written back after every round, so run 50 starts smarter than run 1.
  • A broad model portfolioLinear, kernel, tree-ensemble and gradient-boosting families, feature-engineering moves (polynomial, Yeo-Johnson, scaling), ASHA hyperparameter search, and neural specs routed to a torch execution substrate.
  • Governed autonomyLLM goal-understanding is non-binding: it only proposes; the frozen certifier decides. A per-UTC-day spend cap bounds GPU and LLM cost and degrades to CPU and deterministic proposals. Every "GPU unavailable" is reported with its real reason.

The one invariant that makes it trustworthy

Everything above, the fan-out, the recursion, the LLM, the literature, only ever touches train and validation data. The sealed test is opened once, by frozen code, after the search is over.

The gate is exact math, not a vibe. With k of n sealed predictions correct, certification requires the one-sided exact binomial lower bound to clear the target after multiplicity correction:
